# Browser runtime — demo web app

Runs the `cratefield-runtime-browser-demo` venture (the `waitlist`,
`email-signup` and `cms` modules) entirely in a browser tab: the harness axum
router compiled to wasm, served over sqlite-wasm on OPFS.

## Build & run

The venture is a `cdylib`; `wasm-bindgen` generates the JS glue this page
imports. From the repo root:

```sh
# once: cargo install wasm-pack   (or: cargo install wasm-bindgen-cli)
export RUSTFLAGS='--cfg getrandom_backend="wasm_js"'
wasm-pack build crates/runtime-browser-demo --target web \
  --out-dir ../runtime-browser/web/pkg

# serve the folder (any static server); a normal origin is enough — the
# opfs-sahpool VFS does not require COOP/COEP headers.
python3 -m http.server -d crates/runtime-browser/web 8000
# open http://localhost:8000
```

Press **Boot & run checks**, then **Reload** and run again: the second boot's
migrations should report already-applied, proving the OPFS database persisted.

## Verification status (be honest)

- **Headless-verified (in CI/on the build machine):** every crate compiles to
  `wasm32-unknown-unknown`; the module migrations apply cleanly on plain SQLite
  and are idempotent and composable (`cargo test -p cratefield-runtime-browser`).
- **NOT yet verified in a browser:** the live round trip — sqlite-wasm on OPFS,
  the Service-Worker ingress, and persistence across reload. This page and
  `service-worker.js`/`sqlite_bridge.js` are written to the documented APIs but
  have not been run in a browser. Treat them as the starting point for that
  test, not a proven demo. Likely places to adjust: the pinned sqlite-wasm
  version and its `installOpfsSAHPoolVfs` entry points, and the cms admin
  save payload schema.

## Files

- `index.html` — drives the demo via `callHandle` directly (the most robust
  path to try first).
- `service-worker.js` — the production ingress: intercepts `/api/*` and serves
  it from the wasm venture. Same `callHandle` contract as the page.
- `sqlite_bridge.js` — installs `globalThis.__cratefieldSqlite` over
  sqlite-wasm/OPFS (what the wasm `Database` adapter calls).
- `api.js` — the shared `handle` ⇄ Response contract.
- `pkg/` — generated by `wasm-pack` (git-ignored).

# The template

Every Factory Zero venture gets its own backend: its own Worker, its own
database, its own secrets, its own domain. This repository is the starting
point. Click **Use this template**, edit one file, and the rest is wiring.

> **One file to edit.**
> `src/harness.rs` names the venture, lists the modules, and picks the
> adapters. Everything else in the repo is the same for every venture and is
> kept current by the harness.

Built on the [Factory Zero harness](https://github.com/Factory-Zero/harness)
(Rust, workers-rs, axum).

## What you get

```
Cargo.toml               depends on factory0-core, the runtime, and the modules you want
src/harness.rs           Harness::builder() composition for this venture   ← edit this
src/lib.rs               #[event(fetch)] / #[event(scheduled)] delegating to the harness
tests/harness_builds.rs  asserts Harness::build() is Ok; a bad config fails `cargo test`
wrangler.toml            staging + production envs, D1, rate limit, custom domain, worker-build
migrations/              generated by `fz migrations collect`, committed, never renumbered
justfile                 dev · check · migrate-staging · migrate-prod
smoke.sh                 health, ready, and a signup against a deployed URL
.github/workflows/
  ci.yml                 fmt · clippy · test · fz doctor · worker-build --release
  deploy.yml             main → staging automatically; tag v* → production behind an approval gate
  health.yml             weekly canary against the latest harness crates
```

## New venture checklist

1. **Use this template.** Name the repo `<venture>-backend`.
2. **Edit `src/harness.rs`:** venture name, domain, CORS origins, modules.
3. **Databases.** `wrangler d1 create <venture>-api-staging` and `<venture>-api`; paste the ids into `wrangler.toml`.
4. **Migrations.** `just migrate-staging` runs `fz migrations collect` and `wrangler d1 migrations apply`.
5. **Secrets per environment.** `HARNESS_SECRET`, `RESEND_API_KEY`, `TURNSTILE_SECRET`, `ADMIN_TOKEN`, set with `wrangler secret put`.
6. **Mail domain.** Verify `send.<domain>` in Resend. The subdomain, never the apex, which carries inbound mail.
7. **Custom domain.** `api.<domain>` in the production routes of `wrangler.toml`.
8. **Ship.** Push to `main` for staging. Tag `v0.1.0` for production.

Steps 3, 5, 6 and 7 need a human with dashboard access. Everything else runs in CI.

## Local development

```
just dev        # wrangler dev with a local D1
just check      # fmt, clippy -D warnings, test, fz doctor, worker-build
```

Requires stable Rust with the `wasm32-unknown-unknown` target,
[`worker-build`](https://crates.io/crates/worker-build), and wrangler.

## Status

Template scaffolding is tracked in the [issues](../../issues). It depends on

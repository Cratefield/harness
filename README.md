# Venture backend template

GitHub template for a new Factory Zero venture backend on the
[harness](https://github.com/Factory-Zero/harness) (Rust, workers-rs). Click
**Use this template**, then follow the checklist below.

## What you get (target)

```
Cargo.toml             # depends on factory0-core, runtime-cloudflare, the modules you want
src/harness.rs         # Harness::builder() composition for this venture
src/lib.rs             # #[event(fetch)] / #[event(scheduled)] delegating to the harness
tests/harness_builds.rs# asserts Harness::build() is Ok; fails cargo test before deploy can run
wrangler.toml          # staging + production envs, D1, rate limit, custom domain, worker-build
migrations/            # generated by `fz migrations collect`, committed
.github/workflows/
  ci.yml               # fmt, clippy, test, fz doctor, worker-build --release
  deploy.yml           # main -> staging; tag v* -> production (environment gate)
```

## New venture checklist

1. Use this template; name the repo `<venture>-backend`.
2. Edit `src/harness.rs`: venture name, domain, CORS origins, modules.
3. `wrangler d1 create <venture>-api-staging` and `<venture>-api`; paste ids into `wrangler.toml`.
4. `cargo run -p factory0-cli -- migrations collect && wrangler d1 migrations apply DB --env staging --remote`.
5. Secrets per env: `HARNESS_SECRET`, `RESEND_API_KEY`, `TURNSTILE_SECRET`, `ADMIN_TOKEN`.
6. Verify `send.<domain>` in Resend (subdomain, never the apex).
7. Add the custom domain `api.<domain>` in `wrangler.toml` routes.
8. Push to `main` for staging; tag `v0.1.0` for production.
